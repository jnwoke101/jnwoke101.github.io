01 / The mission

A focused hunt, not a dashboard tour.

The objective was to reconstruct what happened to Haldric Aerospace's engineering segment and translate the findings into a decision-ready CISO brief.

HUNT WINDOW / 14 DAYS
Investigation context

The exercise advisory described GREY VEIL as a state-sponsored threat actor targeting aerospace and defence contractors for intellectual property and persistent access. The hunt tested that scenario against authentication, process, file, network, registry and Sysmon telemetry to reconstruct the local intrusion.

ANALYST ASSESSMENT

High-priority identity and IP exposure.

The findings connect compromised access to domain-controller data staging, an external POST command, and unauthorized port forwarding. Actor attribution is scenario-provided, not independently established by the log artifacts supplied for this writeup.

02 / Attack reconstruction

How far did they get?

An evidence-led sequence, ordered by attack phase. Exact event timestamps were not included in the provided answer sheet; this is not a minute-by-minute forensic timeline.

05 ATTACK PHASES
01
REMOTE ACCESS / Q01–Q05

The first foothold

The investigation identified suspicious activity involving s.brandt, including failed authentication from 185.220.101.34. Four source IPs appeared in the account's connection footprint. The landing host was WS-ENG04.

02
DISCOVERY + CREDENTIAL ACCESS / Q07–Q11

From reconnaissance to account abuse

Queries showed enumeration of Domain Admins and Enterprise Admins and investigation of SRV-DC01 and SRV-FILES02. A memory credential-dump outcome was recorded as NO/none; separate SAM access was identified, but its complete command was not retained in the answer table.

03
LATERAL MOVEMENT / Q13–Q20

The domain controller became a target

The first reconstructed pivot was 10.1.96.114 → SRV-DC01 under m.richter. Activity on the domain controller was associated with WmiPrvSE.exe and originated from WS-ENG04. The attacker staged ntds.dit in a misleading McAfee_Logs directory and used vssadmin in the database-access sequence.

04
PERSISTENCE + EXFILTRATION / Q22–Q29

A return path and an outbound route

On the beachhead, an unauthorized netsh interface portproxy rule exposed port 8443 and forwarded toward SRV-DC01:445; another forwarding rule appeared on the DC. The attack also targeted C:\Engineering\Avionics\A400M_NavSys. Separately, win_update_kb5034.b64 was submitted using a PowerShell HTTPS POST to cdn-telemetry.cloud-endpoint.net.

05
REENTRY + COVER-UP / Q31–Q35

Two days later, the attacker returned

The compromised account was seen again after a two-day gap. The exercise's cleanup sequence included wevtutil cl Security; local log clearing occurred on WS-ENG04 and remote clearing affected SRV-DC01 and SRV-FILES02. Sysmon remained available, allowing the investigation to continue.

03 / The evidence

Signals that changed the assessment.

Four findings connect initial access to measurable exposure. Each references the relevant question identifiers in the supplied investigation sheet.

CORE FINDINGS / 04
FINDING 01 // IDENTITY

Two accounts, multiple systems

s.brandt was linked to the foothold on WS-ENG04; m.richter was used to access SRV-DC01. The scope of affected systems extended to SRV-FILES02 in the cleanup record.

EVIDENCE // Q01, Q05, Q13, Q33
FINDING 02 // CREDENTIAL MATERIAL

Active Directory database staged

The ntds.dit database was staged in C:\Windows\Temp\McAfee_Logs. Defender's MsMpEng.exe interacted with the files, while the exercise notes describe a protection-policy gap.

EVIDENCE // Q16–Q19
FINDING 03 // OUTBOUND TRANSFER

Encoded artifact sent externally

PowerShell's Invoke-WebRequest used a POST with -InFile against win_update_kb5034.b64. The analyst recorded HIGH confidence in credential material exfiltration; the answer sheet does not independently prove remote receipt.

EVIDENCE // Q29, Q35
FINDING 04 // PERSISTENCE

Forwarding survives a password reset

Portproxy configuration is a host-level persistence concern: resetting abused accounts does not by itself remove a configured listener. Clearing Security logs also did not destroy the separate Sysmon event source.

EVIDENCE // Q22, Q24, Q32–Q34

05 / Decision support

What matters to leadership.

Translate technical findings into exposure and immediate defensive priorities, without treating proposed remediation as already completed.

Potential business impact

Identity compromise and engineering IP risk.

Loss of the Active Directory database could expose domain authentication material and enable additional unauthorized access. The separately targeted avionics directory raises a sensitive intellectual-property concern. Available answers support targeting of that directory, not confirmed exfiltration of that exact dataset.

Prioritized containment

Break the return path, then scope exposure.

  • Isolate WS-ENG04, SRV-DC01 and SRV-FILES02 for response review.
  • Remove and validate unauthorized portproxy rules; block confirmed malicious infrastructure.
  • Disable/reset abused credentials, revoke sessions, and assess broader identity impact.
  • Preserve Sysmon telemetry and investigate endpoint protection and detection gaps.
Confidence boundary. The answer sheet provides a high-confidence analyst assessment of credential-data exfiltration and the outbound POST command. It does not include destination-side receipt, the completed package name for the avionics directory, the exact persistence registry path, or evidence that containment actions were performed. All response actions above are recommendations.
