Outcome

Demonstrated both offensive (Red Team) and defensive (Blue Team) skills by taking a real-world style vulnerability from discovery and exploitation through to monitoring and secure remediation.

Project Scenario – BlueDynasty Clinic

BlueDynasty Clinic is a fictional healthcare provider I designed to simulate a realistic SQL injection and defense scenario. The clinic’s appointment portal stores sensitive patient data including names, dates of birth, clinicians, insurance providers, and reasons for visits. A flaw in the appointment search functionality allowed attackers to inject SQL and retrieve all patient appointments, representing a serious PHI exposure and potential HIPAA-style privacy violation.

Red Team Phase – Exploitation

  • • Built a Flask-based appointment search app backed by Azure SQL (BlueDynastyDB).
  • • Intentionally used dynamic SQL concatenation: WHERE P.LastName LIKE '%{search_term}%'
  • • Used payloads like ' OR 1=1-- to bypass filters and dump all appointments.
  • • Demonstrated impact by exposing patient appointments, clinicians, and insurance providers.

Blue Team Phase – Detection & Logging

  • • Designed a SecurityEvents table to capture search behavior and attacks.
  • • Logged normal searches as APPOINTMENT_SEARCH (INFO) and injections as SQL_INJECTION_ATTEMPT (HIGH).
  • • Stored timestamp, source IP, event type, severity, and description for forensic reconstruction.
  • • Wrote events to both Azure SQL and a local log file for investigation.

Secure Remediation – Fixed Search Portal

  • • Created a secure version of the app (app_secure.py) using parameterized SQL queries instead of string concatenation.
  • • Replaced WHERE P.LastName LIKE '%{search_term}%' with WHERE P.LastName LIKE ? and bound parameters from Python.
  • • Added input length checks and SQLI_PATTERN_BLOCKED events when suspicious patterns are received.
  • • Verified that legacy payloads like ' OR 1=1-- no longer return unauthorized data.
